Spring 三级缓存中存的内容，都是围绕着 “单例 Bean 的生命周期管理” 来设计的，它们存储的内容和作用如下：

✅ 一、三级缓存整体结构
Spring 通过 DefaultSingletonBeanRegistry 类维护三个缓存，以下是它们的真实变量名与存储内容：

缓存级别	变量名	类型	存的内容	作用
一级缓存	singletonObjects	Map<String, Object>	已经完整创建的 Bean 实例	最终成品缓存，getBean() 首先查这里
二级缓存	earlySingletonObjects	Map<String, Object>	未完成依赖注入的 Bean 实例	暴露“早期对象”，防止重复创建
三级缓存	singletonFactories	Map<String, ObjectFactory<?>>	创建早期 Bean 的工厂函数（lambda）	延迟创建早期对象，支持 AOP 动态代理

🔍 三级缓存详细说明
1️⃣ 一级缓存 singletonObjects
Bean 的 最终状态，完整经历了构造、依赖注入、初始化、后处理器。

getBean() 默认会先查这个缓存。

只有当 Bean 完全创建完毕后，才会放入此处：

```java
singletonObjects.put(beanName, beanInstance);
``` 

2️⃣ 二级缓存 earlySingletonObjects
存放已经调用构造器但尚未依赖注入的 Bean 实例。

从三级缓存中的 ObjectFactory 生成早期对象后，放入这里，供依赖方使用。

如果有循环依赖，Spring 会从这里取出半成品 Bean：

```java
earlySingletonObjects.put(beanName, earlyReference);
```
3️⃣ 三级缓存 singletonFactories
存放的是一个工厂（ObjectFactory），用于延迟创建早期 Bean 引用。

ObjectFactory 的作用是：返回 Bean 的引用，有时是裸对象，有时是代理对象（结合 AOP）。

示例代码：
```
java
singletonFactories.put(beanName, () -> getEarlyBeanReference(beanName, mbd, bean));
```

🧠 为啥三级缓存不用直接放对象，而用工厂（ObjectFactory）？
这是为了支持 懒加载 + 代理增强（如 AOP）：

有些 Bean 在早期阶段还不确定是否需要被代理（比如加了 @Transactional）。

如果直接把早期对象放进缓存，就无法增强。

用 ObjectFactory 延迟判断，确保能创建增强后的代理对象。

🎯 缓存迁移过程总结
当 Spring 创建一个 Bean 时，三级缓存的迁移顺序大致如下：

```text
ObjectFactory（在 singletonFactories） ──→ 生成早期引用 ──→ 放入 earlySingletonObjects（二级缓存）
                   │
                   └────── getEarlyBeanReference() 可返回代理对象
```
依赖注入完成后：
从 earlySingletonObjects 清除 → 放入 singletonObjects（一级缓存）
✅ 总结一句话
三级缓存分别存的是：最终 Bean 实例、半成品实例、生成半成品的工厂函数，共同配合解决循环依赖 + 支持 AOP。
